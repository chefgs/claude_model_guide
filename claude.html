The three tiers, in one sentence each.

Since Claude 3 (March 2024), every Claude generation has been released as a family with the same naming pattern.

Opus · heaviest

For the hardest things.

Deep reasoning, long-horizon agents, multi-hour coding sessions, complex research. Pay more, wait longer, get frontier intelligence. Opus 4.7 is the current flagship.

  • Complex codebase refactors
  • Multi-step agentic workflows
  • Scientific / legal analysis
Sonnet · the workhorse

The one you'll actually use.

The sweet spot — near-Opus intelligence at ~1/5 the price. Sonnet 4.6 handles 90%+ of production workloads, including most RAG and agent use cases, without compromise.

  • Production RAG pipelines
  • Daily coding assistance
  • High-volume chat backends
Haiku · fastest

For scale and latency.

Sub-second responses at the lowest cost per token. Haiku 4.5 delivers near-frontier intelligence for classification, extraction, routing, and real-time voice/UX loops.

  • Classification & routing
  • Streaming voice agents
  • High-QPS lightweight tasks

Building RAG & agents with Claude.

Capability notes that actually affect architecture choices — and the patterns that hold up in production.

RAG capability by model

What the context window buys you.

All Claude 3+ models handle RAG well, but the right model depends on corpus size and retrieval quality.

  • Haiku 4.5 · 200k — cheap retrieval-heavy flows; fine for short contexts, classification, and citation scoring.
  • Sonnet 4.6 · 1M — the default production RAG choice. Long-enough context to skip aggressive chunking for many corpora.
  • Opus 4.7 · 1M — when synthesis across many documents matters more than cost, or when the agent must reason before retrieving again.
```
Long context ≠ no retrieval

A 1M window doesn't replace a vector store.

Even with 1M tokens, feeding everything every turn is expensive, slower, and hurts quality through lost-in-the-middle effects. Use long context to reduce chunking pressure, not eliminate retrieval.

  • Chunk at semantic boundaries; embed; retrieve top-k.
  • Use prompt caching for stable system prompts + knowledge bases — up to 90% input cost reduction on cache hits.
  • Reserve long context for the retrieved slice plus scratchpad, not the whole corpus.
Tool use / function calling

Native since Claude 3.

All current Claude models support structured tool use via the Messages API. Claude 4.x added parallel tool calls and materially better tool-selection accuracy.

  • Define tools as JSON schemas; the model emits tool_use blocks.
  • Return tool_result blocks on the next turn — the loop is yours to build.
  • For Anthropic-hosted tools, the Model Context Protocol (MCP) is the open standard.
Extended & adaptive thinking

Let the model reason before answering.

Introduced in Claude 3.7 Sonnet. Haiku 4.5 and Sonnet 4.6 support extended thinking with a budget. Opus 4.7 uses adaptive thinking only — the model decides how much to think, tuned via the effort parameter.

  • Big wins on math, code, and multi-step planning.
  • Thinking tokens are billed as output — budget accordingly.
  • On Opus 4.7, temperature/top_p are locked to defaults — use prompting for determinism.
Agent loops

What changed in 4.x.

Claude 4 was the generation where agentic coding and computer-use loops became production-viable. Opus 4.7 adds task budgets — the model sees a running token countdown and self-moderates work to finish gracefully.

  • Plan → call tool → observe → revise. Cap steps explicitly.
  • Use file-system memory (a scratchpad directory) for long-horizon runs.
  • For multi-agent patterns: subagents spawn fewer by default on 4.7 — prompt explicitly if you need them.
Vision for RAG

PDFs, slides, and screenshots.

All current Claude models accept images. Opus 4.7 bumped max image resolution to 2576px (3.75MP) and improved low-level perception — a real unlock for document OCR-style work, chart reading, and computer-use agents.

  • Send PDF pages as images when layout matters (forms, diagrams).
  • Prefer native PDF input when available — cheaper than re-rasterizing.
  • Downsample images before sending if fidelity isn't needed; high-res costs more tokens.
```
One RAG gotcha. Claude's reliable knowledge cutoff (the date through which training data is most dense) varies by model. Always ground time-sensitive answers in retrieved documents rather than model memory, and expose retrieved source citations in the final response — it dramatically reduces hallucination complaints.

Deployment — what breaks at scale.

The things that don't show up in the "hello world" tutorial but always show up in the post-launch retro.

Where to host

Four first-party routes.

  • Anthropic API — fastest access to newest models; simplest integration.
  • Amazon Bedrock — for AWS-native stacks; regional & global endpoints; stays inside your VPC.
  • Google Vertex AI — GCP-native; regional, multi-region, and global endpoints.
  • Microsoft Foundry — newer route for Azure customers.

Model IDs differ across platforms — Anthropic's claude-opus-4-7 is anthropic.claude-opus-4-7 on Bedrock. Plan for an abstraction.

```
Rate limits & capacity

Throughput is not free.

  • Rate limits scale with usage tier — budget for warm-up when launching.
  • Priority Tier (Opus/Sonnet/Haiku) gives committed throughput if you need SLAs.
  • Batch API — ~50% off list price, async 24h window. Ideal for evals, offline enrichment, bulk classification.
  • On Bedrock/Vertex, regional availability for the newest models lags the Anthropic API by weeks.
Cost optimization

The levers, in order.

  • Prompt caching — cache stable system prompts, tools, and document context. Often 70–90% input cost reduction.
  • Right-size the model — demote from Opus → Sonnet → Haiku with evals at each step.
  • Bound max_tokens — Claude's default is verbose; cap it.
  • Effort / task_budget (4.7) — let the model self-moderate reasoning spend.
  • Batch API for anything not user-facing.
Observability

Log what you'll need to debug at 3am.

  • Full request + response (redacted for PII), token counts, model+version ID, latency.
  • Tool-use traces: which tool, args, result, retries.
  • Cache hit rates if using prompt caching.
  • Refusal/filter events — fire-hose these to a review queue.
Security & compliance

Treat the model like any other external service.

  • Never send secrets, PII, or customer data without a reviewed DPA. Anthropic offers Zero Data Retention for enterprise.
  • On Bedrock/Vertex, data stays within your cloud boundary — preferred for regulated industries (HIPAA, PCI, India DPDP).
  • Validate and sandbox all tool execution — the model will occasionally call tools you didn't expect.
  • Guard against prompt injection in retrieved documents: treat retrieved text as untrusted input.
  • Rate-limit per-user at your gateway; LLM APIs are a great DDoS amplifier if you don't.
Model lifecycle

Your model will be deprecated.

Anthropic gives ≥60 days notice before retirement. Plan for migrations from day one.

  • Pin to dated snapshots (e.g. claude-haiku-4-5-20251001) — aliases float and can change behavior silently.
  • Keep a golden eval set. Re-run it on every candidate model before migrating.
  • Watch tokenizer changes — Opus 4.7 ships a new tokenizer that can use up to 35% more tokens on the same text.
  • Audit usage via the Console → Usage export to find stragglers before retirement day.
Agentic deployments

Guardrails that aren't optional.

  • Step caps on every loop — always. Runaway agents are expensive.
  • Action allow-lists — enumerate every tool; deny by default.
  • Human-in-the-loop for destructive actions (delete, email, payment).
  • Per-run budget — both tokens ($) and wall-clock.
  • Idempotency keys on external side-effects so retries don't double-fire.
Regional considerations

Where the data lives matters.

  • India / APAC: use Bedrock/Vertex regional endpoints for residency; factor in cross-region latency if the model isn't yet local.
  • EU: Vertex EU multi-region or Bedrock EU regions for GDPR residency.
  • US gov / regulated: Bedrock with VPC endpoints; verify FedRAMP status per model.
  • Global endpoints optimize availability but cross borders — check your compliance posture.
```
A good starter stack. Sonnet 4.6 for the main reasoning path · Haiku 4.5 for classification/routing · prompt caching on everything stable · Batch API for evals and offline jobs · pinned dated snapshots · a golden eval set you run before every model bump. Add Opus 4.7 only where Sonnet's evals miss.
